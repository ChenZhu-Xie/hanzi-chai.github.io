# 有向笔画墨迹扩散模型

本文规定一种用于 Unicode PDF 字源拆分的最小物理模型。它不把
hanzi-chai candidate 当作可以缩放、拉伸后覆盖到 PDF 上的几何模板；
candidate 只是一份**符号化书写假说**，PDF 则只提供真实墨迹边界和由其
导出的骨架路网。

## 1. 输入及可信边界

### Candidate 提供的硬约束

- 递归结构树、叶部件 ID、同一部件的 occurrence；
- 有向笔画的数量、顺序和部件归属；
- 每笔的类别以及笔内命令顺序；
- 笔画的起笔方向、转折次序和收笔方向；
- `⿰`、`⿱`、包围、穿插等离散结构关系。

仓库中的路径数组顺序也必须经过人工确认的语义笔顺修正。目前已确认
486 号断开草字头为 `横、竖、竖、横（一丨丨一）`，而非旧路径数组的
`竖、横、竖、横`。修正作用于叶部件，因此所有复用 486 的字形一致受益；
旧标注按“部件 ID + 笔画类别”做稳定重排，不改写原始 JSON。

这些约束只说明“如果当前 candidate 正确，应当找到什么”，不能证明它
就是当前 PDF 字源的答案。

### Candidate 只提供弱先验的信息

- 部件和笔画的大致左右、上下次序；
- 起点在所属部件中的粗略方位；
- 长短、间距和弯曲程度。
- 笔画之间的接触、相交、分离和端点重合关系；
- 接触点在两条有向笔画各自弧长上的角色（起段、中段或末段）。

弱先验只能在两个拓扑解完全打平时排序，不能否决满足硬约束的解。
U+808E「肎」T 源证明 sibling candidate 的接触图也可能不同：candidate
认为第 5、6 笔相接，而 PDF 真值中二者分离。因此接触关系必须由 PDF
骨架复核，不能作为硬约束强迫目标字源服从 candidate。

### 不得从 Candidate 迁移的信息

- 绝对坐标、尺寸和长宽比；
- 精确占据区域和部件边界；
- 精确笔宽、曲率和字体装饰；
- 由 candidate 色块直接投影得到的 PDF 颜色。

上色必须是笔画识别和部件归属完成后的结果，不能反过来作为识别前提。

## 2. PDF 墨迹域和骨架图

1. 直接提取 PDF 矢量轮廓并栅格化为封闭二值墨迹域 `Ω`；不复用 PDF
   内嵌字体轮廓作为项目数据。
2. 对 `Ω` 做 Zhang–Suen 细化，得到一像素骨架 `S`。
3. 对骨架像素按顺时针八邻域计算 crossing number：
   - `1`：端点；
   - `2`：普通路径；
   - `>=3`：十字、丁字或任意形状的路口。
4. 将相邻路口像素聚为一个逻辑路口，并把路口之间的骨架链压缩为有向
   候选边。骨架图只描述真实 PDF 的可通行道路，不自带笔画身份。
5. 同时计算墨迹域内的边界距离。它只控制横向填墨速度和停止位置，不
   参与决定在路口选择哪一条主路。

这里借鉴了以下工作，但采用更适合汉字有向笔画的约束：

- [skeleton-tracing](https://github.com/LingDong-/skeleton-tracing)：把细化骨架
  转成折线及路口；
- [Skan](https://github.com/jni/skan)：把端点、路径和路口转换成图；
- [OpenCV floodFill / distanceTransform](https://docs.opencv.org/4.x/d7/d1b/group__imgproc__misc.html)：
  有边界区域扩散和距离标签；
- [arc_line_vectorization_suede](https://github.com/mitmedialab/arc_line_vectorization_suede)：
  在路口以切线、曲率和真实墨迹可达性重新连接被切断的骨架链。

## 3. 第一笔起点的寻找

对当前 candidate 笔画 `cᵢ`，在尚未被解释的 PDF 骨架上枚举端点、路口和
必要的普通路径点作为种子。每个种子只由下列证据评分：

1. **起笔切线**：种子的至少一条出边与 `cᵢ` 的起笔方向相容；
2. **笔内方向语法**：从该种子出发能否依次实现 `cᵢ` 的方向和转折；
3. **笔画拓扑**：起点是悬空、接触旧笔、还是位于交点，必须与 candidate
   中该笔和此前笔画的关系相符；
4. **有向接触角色**：候选中的“起点对起点”“中段对起点”和“末端对
   中段”不可互换；比较的是无尺度弧长阶段，而非 candidate 的空间坐标；
5. **笔顺可用性**：不能无理由重复已经归属其他笔画的整段骨架；真正的
   交点和共享端点允许零长度重合；
6. **部件状态**：已经关闭的叶部件不得重新进入；当前 occurrence 只能
   消耗自己的连续笔画区间；
7. **结构序位**：只在前六项打平时，才用上下、左右等粗序位破平；禁止
   使用 candidate 的绝对坐标距离作为主要分数。

若第一名和第二名不能被硬约束区分，则起点是歧义的，不能偷偷选择离
candidate 坐标最近的一个。

## 4. 有向主扩散与横向沾染

扩散分成两种不同速度、不同职责的波：

### 4.1 主扩散前沿

- 只有一个主前沿，沿骨架从 pen-down 向 pen-up 前进；
- 普通路径上只能继续前进，不能掉头；
- 到路口时，枚举每条尚可用的出边；
- 出边必须满足当前笔剩余的方向/转折语法、与此前笔画的交点关系以及
  后续笔画仍可完成的条件；
- 硬约束只剩一条出边时才通过；多条出边仍成立时保留分支假说，不能用
  最近 candidate 色块强选；
- candidate 的当前笔走完以后，主前沿只能在端点、合法收笔点或已满足
  该笔拓扑关系的位置停止。
- 若 candidate 的收笔端没有接触后续笔，而 PDF 当前骨架点仍存在与入射
  切线同向的未消费出口，并且当前路线相对 candidate 的全字归一化长度
  明显过短，则视为“主路中途截断”，不得在此收笔。长度只作此处的佐证，
  不能单独决定路线；否则合法终止在交点的笔画会被误罚。

### 4.2 横向圆形沾染

- 每个已经被主前沿到达的骨架点同时发出各向同性的横向墨迹波；
- 横向波只能在 PDF 墨迹域 `Ω` 内传播，碰到轮廓立即停止；
- 横向波不得越过尚未被主前沿批准的路口闸门；
- 多笔横向波相遇时形成分水岭。交点处允许重合身份；不能确定层属的
  小区域标成歧义，而不是强塞给最近笔画；
- 横向填墨只负责恢复笔宽，不改变主前沿所决定的笔画道路。

因此它不是普通二维 flood fill，而是“骨架上的有向一维推进 + 墨迹域内
受闸门约束的二维横向扩散”。

## 5. 笔画、部件和整字的终止

一笔终止需要同时满足：

1. candidate 的方向和转折序列已消费完；
2. 当前前沿到达合法 pen-up；
3. 所有已到达路口的其他出口都被笔画、笔顺、部件或未来可完成性约束
   排除；
4. 没有为了追求覆盖率而进入不属于本笔的分支；但评分必须奖励覆盖的
   **绝对骨架像素数**，不能只奖励“本路线中有多少比例是新像素”，否则
   很短却完全未复用的错误路线会胜过完整长笔画。

一个叶部件终止需要：

- 它的全部连续笔画均已终止；
- 这些笔画的交点/接触图与候选叶部件相符；
- 墨迹没有无法解释的必要分支；
- 关闭后不再被后续笔画重新进入。

整字结束后反查：笔画覆盖、重复道路、未解释骨架、部件边界、候选兄弟
差异以及所有歧义。若没有 candidate 能完整解释，则输出“需要新兄弟部件
/新部件/新字形”或“PDF 笔画仍有歧义”，而不是选择最像的旧 candidate。

PDF 墨迹连通岛与语义叶部件不一一对应。多个相接叶部件可以共用一个岛，
一个含离散点画的叶部件也可能跨岛。映射只允许使用全字的粗左右列、上下
次序；不得在数量不等时把所有叶部件塞进最大岛。骨架转角必须先去除一像素
细化毛刺再计算，否则路口锯齿会把直笔误报成多次转折。

若未解释骨架比例过高、全局第一/第二解近乎并列，或某笔只能从很靠后的
局部候选中勉强选择，结果状态必须为 `needs-review`。这通常表示当前 source
改变了 candidate 的笔画语法或需要新 sibling；低置信结果不可进入 apply。

## 6. 笔画类别退化

当前数据库允许以下条件变体，不因此新建兄弟部件：

- 提可退化为横；
- 点、捺、横捺可视为同类；
- 竖与竖钩的字体装饰可忽略；
- 竖弯钩与竖提的局部装饰可忽略。

不可退化的强证据包括：多/少一笔、一笔对两笔、绝对竖的有无、交点是否
重合、中竖是否穿横后继续、连接对分离、折向和开口方向。

## 7. 可复现评测协议

每次修改规则均执行：

1. 对某目标人工真值做留一：预测阶段不得读取目标 JSON；
2. 冻结每笔起点、路口选择、终点和部件归属；
3. 才读取人工真值，报告起点/终点误差、方向一致率、有向序列 DTW、
   转折位置、经过的骨架关键节点、逐笔覆盖 precision/recall/IoU、部件
   边界 precision/recall、未覆盖骨架和错误分支；部件 IoU 不得替代逐笔 IoU，
   因为同一部件内的错误笔画交换仍可能得到 100% 部件 IoU；
   “有向序列”只约束 pen-down 到 pen-up 的逻辑先后。人工绘制速度、停顿、
   采样点密度和相同百分比时刻均不是真值；DTW 允许局部任意加速/减速，
   但禁止倒序经过转折点或拓扑节点；
4. HTML 必须能逐时刻拖动，显示主前沿、横向扩散、当前笔、路口决策及
   停止原因；人工真值也按笔顺逐笔回放。直线、折线等稀疏标注须按弧长
   在相邻控制点间连续插值，不能按控制点个数截断，否则二点直线会在中途
   突然整段出现。当前笔必须准确到达标注的最后一点，未来笔不得提前显示；
5. 人工真值的小范围手抖误差只影响连续指标，不改变笔画数、方向、拓扑
   和部件 ID 等离散真值。

第一阶段只在既有人工标注上迭代；通过逐字视觉验收后，才允许盲测作者
新增完成区，更不能直接写远端数据。

## 8. 从青色人工有向笔画学习

训练单元不是“长得像的一笔”，而是精确签名：

`叶部件 ID | 该叶部件内第几笔 | 该叶部件总笔数 | 笔画类别`

这样 1128 的第一笔不会和形近兄弟的第一笔混训；同 ID 的重复 occurrence
保留在原始证据中，但共享该叶部件的笔画规则。每条人工笔画保留下列可审计
事实：起点、起向、在全字和部件中的归一化位置、是否接触此前笔画、所经过的
真实骨架路口，以及在每个路口实际选择和拒绝的方向。

这些事实不能同等进入评分：

- 起点在当前骨架上表现为端点、普通路径还是路口，只作解释。相邻笔画与它
  相交，就足以改变 crossing number，这不是稳定的跨字源语义。
- 同一精确签名在多个独立字源中的全字归一化起点方差足够小时，起点区域才
  作为有上限的弱先验；起笔方向一致时也只作小幅破平。
- 路口规则比较“已经遇到的路口该往哪走”，不比较路口数量。不同字体的细化
  骨架可能把一个路口拆成两个，或者完全吞掉；缺少被检测到的路口不能受罚。
- 训练样本一致选择直行，而目标路线明确左/右转时，才产生有上限的反例惩罚。
- 一个样本只生成解释；排除当前目标后至少还有两个独立 case，规则才可影响
  路线排序。

预测必须先冻结，之后才读取目标人工真值。当前的训练器输出原始样本、按签名
聚合的规则和人类可读报告；预测器使用 `--learned-rules` 加载规则，并把目标
`U+XXXX-source` 从支持样本中移除。因此同一份人工 JSON 不可能既当答案又给
自己的预测打分。

第一轮实验也留下了一个重要负例：直接惩罚“起点骨架角色不同”和“路口序列
长度不同”，会把 11 个留一 case 的平均有向 DTW 从 8.755% 恶化到 10.099%。
删除这两个不稳定假设、改用上述保守规则后，平均有向 DTW 为 8.343%，平均
起点误差从 11.019% 降至 10.520%，逐笔宏 IoU 从 0.559 升至 0.586，部件宏
IoU 从 0.748 升至 0.761。该结果只证明这些规则在当前小样本上值得保留，尚不
证明可以脱离 `needs-review` 自动写库。
